# Motion specification

Internal navigation (header, wordmark, section and project links, detail back/next and 404 return) uses `next/link`. These remain real `href` links for keyboard, direct-load and static export; with JS available, App Router handles ordinary in-site navigation without a full document reload. External, email, in-page skip/back-to-top and blank résumé anchors retain native behavior. Browser fallback can reload if JS is unavailable. No navigation blocking or manual transition timers are introduced.

On initial load and when a new page's `<main>` mounts after an App Router route change, CSS runs a single 280ms ease-out from 97% opacity and +6px vertical offset to its normal position. Content is never fully hidden; there is **no exit transition** or delayed navigation. A link hovered in the project directory moves 3px over 200ms, and ordinary links gain a thin underline; keyboard focus retains its high-contrast outline. The hero torus is a decorative Three.js line-segment mesh loaded after it enters the viewport; it rotates slowly, eases toward pointer position and pauses the render loop when offscreen. Per-fiber cool color intensities drift at a capped ~18 updates/second by mutating the existing GPU color buffer (no per-frame arrays), with no flashing or discrete random jumps. Pixel ratio is capped at 1.75; renderer and GPU geometry/materials are disposed on unmount. Static toroidal SVG remains visible before hydration and if WebGL fails, the context is lost, or reduced motion is enabled. Under `prefers-reduced-motion: reduce`, CSS forces the fallback visible and the canvas hidden even if the JS media-change listener has not run; the render loop checks the preference and stops, main animation is disabled, and scrolling is immediate. When the listener runs on re-enable, it renders once before showing the WebGL canvas. The mobile menu retains its `aria-expanded` toggle and closes on link activation.

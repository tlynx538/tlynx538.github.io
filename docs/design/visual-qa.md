## Review pass 3 — interaction and responsive checks

Headless Chrome with device emulation recorded `innerWidth === scrollWidth` on the homepage at 1440, 1280, 1024, 768, 390 and 360px; this establishes no page-level horizontal overflow there, **not** a complete accessibility audit of all routes. At 390px the menu toggle became visible and its `aria-expanded` changed false → true after a click and render; the blank `href=""` résumé click preserved the current URL. With the final `next/link` source, a mobile menu click navigated Home → Projects and closed the menu; a project link opened its detail, and browser back returned to Projects. A page-global marker survived both navigations, showing no full document reload. Direct-load `/projects/tafsiri-s2st/` succeeded; exported `/`, `/projects/`, one detail, `/career/`, `/about/`, `/contact/` returned HTTP 200 under a local static file server, while `/writing/` and `/missing/` returned 404. Reduced-motion emulation matched `(prefers-reduced-motion: reduce)` and computed `scroll-behavior: auto`. Local export paths are direct-loadable with trailing slashes; actual GitHub Pages host behavior, iOS Safari, touch/trackpad feel, screen-reader reading order, keyboard-only end-to-end flow, and the configured résumé URL opening a new tab were not tested.
